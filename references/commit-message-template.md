# Commit Message Template

Use the repository's existing convention first. If none exists, use Conventional Commits.

```text
type(scope): imperative summary

Explain why the change is needed and include relevant context.

Refs: #123
```

## Subject
- Use an accurate type such as `feat`, `fix`, `refactor`, `docs`, `test`, `build`, `ci`, or `chore`.
- Keep the subject concise and imperative.
- Avoid trailing punctuation.
- Add a scope only when it improves clarity.

## Body
Explain motivation, behavior, and trade-offs. Do not narrate every changed file.

## Footer
Add issue references or breaking-change notes only when accurate and verifiable. Never invent issue numbers.
